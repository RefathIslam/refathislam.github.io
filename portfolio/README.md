## Repository layout

```
portfolio/
├── index.html                  # the whole site — one page, semantic sections
├── .nojekyll                   # tells GitHub Pages to serve files verbatim
├── LICENSE
├── README.md
└── assets/
    ├── css/style.css           # design tokens + all styling
    ├── js/lattice.js           # spatial prisoner's dilemma simulation (hero canvas)
    ├── cv/Md_Refath_Islam_CV.pdf
    └── img/
        ├── profile.jpg         # 640×640 headshot
        ├── award-forum86.jpg   # Forum 86 Research Excellence Awards Ceremony 2026
        ├── msc-defense.jpg     # MSc thesis defence, Dept. of Mathematics, BUET
        └── papers/             # one optional figure per publication — see its README
```

There is no `_config.yml`. The site is deliberately **not** Jekyll-built — `.nojekyll`
switches the Jekyll pipeline off so that what is committed is exactly what is served. Site
metadata lives in the `<meta>` tags at the top of `index.html`.

## Publishing it

1. Create a repository named **`portfolio`** under the GitHub account **`refathislam`**.
2. Push the contents of this folder to the `main` branch:

   ```bash
   git init
   git add .
   git commit -m "Portfolio site"
   git branch -M main
   git remote add origin https://github.com/refathislam/portfolio.git
   git push -u origin main
   ```

3. In the repository, go to **Settings → Pages**, set *Source* to **Deploy from a branch**,
   branch **`main`**, folder **`/ (root)`**, and save.
4. The site goes live at `https://refathislam.github.io/portfolio/` within a minute or two.

### Using a different repository name

Every internal link is relative (`assets/...`), so the site works at any path without
changes. If you publish it as `refathislam.github.io` instead, the site is served at the
bare domain and nothing needs editing.

### Custom domain

Add a file named `CNAME` at the root containing only your domain (e.g. `refathislam.com`),
then point a `CNAME` DNS record at `refathislam.github.io`.

## Editing the content

Everything is in `index.html`, in the order it appears on the page. Each section is marked
with an HTML comment banner.

| To change | Edit |
|---|---|
| Name, tagline, stat counters | `<section class="hero …" id="top">` |
| Research interests | the `<ul class="chips">` list in `#research` |
| MSc thesis write-up | the `<article>` inside `#thesis` |
| Project cards | `<article class="card">` blocks in `#projects` |
| Publications | `<li>` items in the `<ol class="bib">` lists in `#publications` |
| Talks, education, experience, certificates, leadership | `<div class="entry">` blocks — each is a date rail plus a body |
| Contact intro and links | `#contact` |
| Colours, type, spacing | the `:root` token block at the top of `assets/css/style.css` |
| The hero simulation | `assets/js/lattice.js` — `L`, `THRESHOLD`, `BURN_IN`, `FPS` |

**Adding a publication.** Copy an existing `<li>` in `<ol class="bib">`, paste it at the top
(the list is newest-first) and edit the four parts: title, author line, venue line, DOI link.
Keep `<b>Md. Refath Islam</b>` around your own name — that bolding is what lets a reader find
you in a long author list. The `01`, `02`, … numbers are generated by CSS, so you never
renumber anything by hand.

**Giving a paper its own figure.** Every publication entry has a thumbnail slot wired up.
Put an image in `assets/img/papers/` under the filename listed in
[that folder's README](assets/img/papers/README.md) and it appears next to the paper — no
HTML to edit. If the file is not there, the entry hides its thumbnail and renders as plain
text, so partially-filled lists still look deliberate. To add a figure for a *new* paper,
copy the `<figure class="bib__fig">` block from a neighbouring entry and change the filename
and `alt` text.

**Moving a paper from "Under review" to published.** Cut the `<li>` out of the second
`<ol class="bib">`, drop it into the first, swap the `pill` spans for a real venue line with
its DOI, and bump the "Under review" counter in the hero.

## The hero animation

`assets/js/lattice.js` runs rock–paper–scissors on a 160 × 160 periodic lattice as a cyclic
cellular automaton. Each cell holds one of three strategies in a cyclic dominance loop — rock
crushes scissors, scissors cut paper, paper covers rock — and is invaded once at least
`THRESHOLD` of its eight neighbours hold the strategy that beats it:

```
next(c) = c+1 (mod 3)   if  #{neighbours in state c+1} >= THRESHOLD
          c             otherwise
```

No strategy can win, so the lattice never settles; random noise organises itself into rotating
spiral waves. Blue is rock, gold paper, vermilion scissors.

| Constant | Default | Effect |
|---|---|---|
| `L` | `160` | lattice size — larger gives finer spirals |
| `THRESHOLD` | `3` | invasion threshold out of 8 neighbours. `2` mixes into noise, `4` freezes |
| `BURN_IN` | `180` | generations run before the first paint, so the page opens on spirals rather than noise |
| `FPS` | `10` | animation speed |

The simulation pauses when it scrolls out of view, and under `prefers-reduced-motion` it paints
the burnt-in frame once and holds it.
